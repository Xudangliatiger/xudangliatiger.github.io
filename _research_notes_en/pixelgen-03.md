After exploring Dual-level AR, we moved to a hybrid architecture that combines latent autoregression with pixel diffusion.

## Method C: a hybrid AR + diffusion architecture

We retain Semantic AR, but replace pixel regression with a diffusion model.

### Why try this combination?

#### 1. Composite semantics no longer conflict with sequential pixel decisions

If the semantic AR stage does not sample, a second autoregressive stage must process both a multimodal semantic feature and pixels that may already have committed to one of its modes. This can create contradictions later in the sequence.

Diffusion avoids that specific failure mode. At each sampling step, it updates all pixels in the patch together, so a semantic choice can be resolved jointly rather than one pixel at a time.

#### 2. Pixel diffusion can own multimodal sampling

In this architecture, AR supplies a multimodal semantic representation and diffusion produces the final pixel sample. This is almost the reverse of the TiDAR principle, “think in diffusion, talk in autoregression.” Which ordering is better is an empirical question.

An alternative is to let Semantic AR sample first, then condition pixel diffusion on the selected semantic feature. We should compare both distributions of responsibility.

#### 3. MAR suggests that the design should be viable

[MAR](https://arxiv.org/abs/2406.11838) combines autoregression and diffusion over latent features. A $16 \times 16 \times 3$ pixel patch is simply a continuous vector of length 768, so there is no structural reason the same idea cannot operate directly on pixels.

### CFG in a multi-stage generator

Conventional classifier-free guidance has a clear conditional and unconditional branch:

- **Conditional:** the model receives condition $c$, such as a class, prompt, or text embedding.
- **Unconditional:** $c$ is replaced by a null token or empty prompt.

The guided output is

$$
\mathrm{pred}_{\mathrm{cfg}} = \mathrm{pred}_{\mathrm{uncond}} + s \cdot \bigl(\mathrm{pred}_{\mathrm{cond}} - \mathrm{pred}_{\mathrm{uncond}}\bigr).
$$

Here, $\mathrm{pred}$ can be an $\epsilon$-, $x$-, or $v$-prediction, or autoregressive logits. The formula is independent of the parameterization; $s$ is the guidance scale.

The hybrid model has more than one condition. Pixel diffusion receives at least:

1. An external condition $c$, such as a class or prompt.
2. A semantic feature $z$ generated by Semantic AR, possibly still representing multiple modes.

The main design question is therefore: **what should the unconditional branch remove?**

#### Guidance through the semantic representation

The most natural formulation is to prevent the pixel generator from seeing $c$ directly. Its only condition is the semantic representation $z$:

- $z_c = f_{\mathrm{AR}}(c)$
- $z_{\varnothing} = f_{\mathrm{AR}}(\varnothing)$

The pixel generator evaluates

- $\mathrm{pred}(x_t \mid z_c)$ for the conditional branch, and
- $\mathrm{pred}(x_t \mid z_{\varnothing})$ for the unconditional branch.

Guidance becomes

$$
\mathrm{pred}_{\mathrm{cfg}} = \mathrm{pred}(x_t \mid z_{\varnothing}) + s\Bigl(
\mathrm{pred}(x_t \mid z_c) - \mathrm{pred}(x_t \mid z_{\varnothing})\Bigr).
$$

The operation is therefore guidance between semantic representations rather than direct guidance in pixel space.

The hard part is conceptual. Conditioning is now hierarchical, not a single prompt. How we define the unconditional representation determines what the guidance actually encourages.

## Designing the pixel decoder

The multimodal output of Semantic AR suggests that the pixel decoder needs more capacity than a lightweight pixel-diffusion head. Semantic diffusion already receives the current noisy pixel value and often solves a more locally single-mode problem. Decoding exact pixels from a semantic representation requires more information and potentially more parameters.

### 1. MLP mixer

The simplest option is to widen an MLP mixer. However, it does not explicitly model interactions among pixels. Our implementation produced substantial high-frequency noise, for reasons that remain unclear.

### 2. Pixel attention

With explicit attention, increasing the per-pixel dimension to 128 exhausted memory. The number of input elements is 256 times larger than at the patch level. It is unlikely that each pixel needs such a wide embedding; recent designs often use 16 or 32 dimensions.

### 3. Width and pixel AdaLN

Increasing the dimension from 16 to 64 improved performance. But applying pixel-wise AdaLN at that width would require roughly 400M parameters. Ordinary AdaLN preserved performance with the MLP mixer but degraded the attention model.

One possible compromise is to keep a narrow representation through pixel AdaLN and expand it only before attention, where a wider multi-head representation can mediate pixel interactions.

### 4. Number of heads

At dimension 16, changing from one head to four improved performance. Pixel interaction needs to carry more than raw pixel values: it may represent patch semantics, material, lighting, and other upstream features. Multiple heads allow different interaction patterns. On a face partly shaded by a hat, for example, semantic identity may be related to similar facial pixels while luminance is controlled by illumination and reflection.

At dimension 64, moving from one head to four caused a severe quality drop and many noisy points. One interpretation is that each head still needs around 64 dimensions, which returns us to conventional attention and its high cost.

### 5. MLP width after attention

Increasing the MLP from $4 \times \mathrm{dim}$ to 1,024 dimensions gave a small improvement. It adds only roughly 1–10M parameters, yet its computational cost is disproportionately high. The benefit does not currently justify the expense.

Even after returning to dimension 64 with a single head, noise remained. This may be an implementation problem: we inserted a dimension-changing MLP before input attention, so the next check is to remove that projection.

## Stopping the pixel-attention branch

These experiments suggest that explicit attention between every pixel may not be necessary and is consuming too much iteration time. Even the global-attention formulation does not truly create unrestricted interaction in this design. A simpler MLP mixer may be enough.

## Reusing an existing decoder

We also tried the DeCo decoder. It has an interesting property: it uses no MLP mixer. In our setup, however, it performed even worse.

This result raises another possible interpretation: perhaps a pixel is best viewed as a projection of high-dimensional information into a low-dimensional observation. But the current evidence still indicates that some form of mixing between pixels is necessary.

The remaining question is now narrower and more actionable: **what is the least expensive mixer that provides enough pixel interaction without spending most of the model's parameter and compute budget?**
