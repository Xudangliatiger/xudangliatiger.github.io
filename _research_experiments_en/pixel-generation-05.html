01 / Interface

Replace the codebook token with downsampled RGB

The one-step decoder in the previous record still depended on a pretrained tokenizer. v0.16.8 makes the most direct substitution: instead of predicting a code id, the Semantic AR model predicts a low-resolution RGB scaffold r_t. A one-step decoder reads both sampled RGB and hidden state h_t to render the full patch.

Goal

Maintain Pixel input → Pixel state → Pixel output without a VQ codebook. Coarse RGB should carry the mode and layout, while hidden state supplies the remaining information.

The design retains two paths: a sampled-value path carries the coarse RGB decision forward, while a hidden-state path carries information about the distribution that has not been reduced to one sample. It is more multimodal than pure regression and more pixel-native than a tokenizer-based system.

02 / Observation

Layout emerges, but detail does not recover with resolution

v0.16.8.5c free runs: low-resolution RGB conveys rough color, layout, and identity, while boundaries and textures remain blurred or periodically block-structured.

This is not a total generation failure. The samples show that coarse RGB is a useful layout hint. The issue is that it does not uniquely determine a high-resolution patch. Two decoding choices expose two different symptoms:

PathModel behaviorVisible symptom
Mean / regressionAverages several plausible detailsWashed textures and soft edges
Sampled coarse RGBTreats one low-resolution draw as a hard downstream conditionSampling drift becomes grid/patch artifacts

03 / Diagnosis

Low-resolution RGB is a statistic, not a recoverable mode index

A 1×1, 2×2, or 4×4 RGB value describes local mean color and coarse shape. Many textures, edge locations, and object details downsample to the same value. In general:

\[H(X_{\mathrm{high}}\mid R_{\mathrm{low}}) \gg 0.\]

This differs from the codebook-like representation in v0.16.7. A learned mode token can encode high-resolution patch identity deliberately; low-resolution RGB was never trained as an invertible index. A positive v0.16.7 result therefore does not imply that raw coarse RGB is sufficient.

CODEX_LOG records similar periodic block noise in both v0.16.8.x and later v0.17.2.x branches. Repetition across branches makes coarse-sample distribution drift a more credible account, but decoder capacity, train/inference mismatch, and independent patch sampling may still contribute.

04 / Conclusion

Pass belief forward, not only a single coarse sample

  1. 01

    Established: coarse RGB carries layout

    Object class, dominant color, and large-scale spatial structure are visible in free runs.

  2. 02

    Established: mean decoding removes detail

    When one low-resolution value maps to several patches, a deterministic renderer moves toward the conditional mean.

  3. 03

    Working account: hard sampled RGB accumulates errors

    Once a coarse sample leaves the training distribution, downstream levels treat it as fact rather than repairing it.

  4. 04

    Architectural requirement: separate value and belief

    The sampled value records a committed choice; hidden state should preserve a distribution summary for the next scale.

05 / CascadeAR check

Splitting the jump into scales does not remove ambiguity automatically

v0.17.4–17.5 then replaces the one-step 1 → 16 jump with a [1,2,4] CascadeAR and tests sampled values, hidden conditions, and residual targets in actual runs. The evidence is more specific than the single-scale experiment, but it still does not establish coarse-RGB sufficiency.

v0.17.x branch summary. Alternative histories, conditions, and residual paths change the failure mode without reliably removing blocks or recovering detail.

The precise conclusion is not that low-resolution RGB is universally and strictly insufficient. It is that, under these interfaces, capacities, and training settings, coarse RGB does not carry enough recoverable detail, while extra levels and condition paths do not reliably cure sampled-history drift.

06 / Next step

Do not ask one coarse RGB token to explain a full patch in one jump

The natural repair is to split the 1 → 16 jump into several RGB resolutions and model a new distribution at every scale. The next stage therefore branches into two questions: grouped pixel ordering with diagonal and column AR, and CascadeAR experiments that isolate how sampled values, hidden conditions, and cross-attention should enter the next resolution.
