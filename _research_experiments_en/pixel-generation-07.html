01 / Hierarchy

Write several RGB resolutions into one token sequence

CascadeAR uses separate modules for each resolution, creating many cross-level interfaces and confounding capacity with information flow. v0.17.7 Hierarchical Pixel AR uses one shared backbone instead. Every macro patch forms token groups at 1×1, 2×2, and 4×4; all groups are concatenated into one causal sequence.

\[S=[S_{L1};S_{L2};S_{L4}],\qquad H=\mathrm{Transformer}_{\theta}(S).\]

Value dimensionality varies by scale, so RGB encoders and DMoL heads remain level-specific. The Transformer, causal attention, and most parameters are shared. RoPE repeats the patch grid at each level, while learned level embeddings distinguish resolutions.

Objective

If one causal space can represent both coarse belief and fine refinement, it reduces interface differences and lets every fine token read the full earlier context.

03 / Results

The shared model refines progressively, but fine levels do not reliably repair the coarse branch

v0.17.7 L1, L2, L4, and deterministic decoder0. Later rows raise nominal resolution and sharpen slightly, but do not consistently repair an incorrect object structure or boundary selected at L0.

The positive result is clear: L0 produces class-related color and layout, and the shared Transformer carries those states into finer levels. The hierarchy is trainable. The cost is also clear: three levels repeat patch-grid sequence positions three times, and the observed training cost is roughly three times the single-level setup.

Fine DMoL heads predict multiple RGB values in parallel within one token. They read the same coarse context but lack sufficient within-patch coordination. Hotter sampling tends to add salt-and-pepper noise; colder sampling tends toward smooth averaging.

04 / Failures

Parameter sharing does not automatically remove three error sources

  1. 01

    Incorrect coarse choices

    Once L0 samples a wrong color, layout, or local mode, later levels usually inherit it rather than overturn it.

  2. 02

    Insufficient coordination inside parallel DMoL

    A fine token samples several pixels together; uncertain edges can lead those pixels to select incompatible modes independently.

  3. 03

    Exposure bias grows with depth

    Training sees GT history while inference sees sampled history. Every added level creates another opportunity for drift.

Early Patch-MDN results do not clearly fix these issues, but their training budget is not matched to the DMoL baseline. We therefore do not claim that DMoL is generally superior. The supported statement is narrower: under the observed checkpoints, changing the output distribution family alone is insufficient.

05 / Decision

Locate the first error before adding more hierarchy

HPA has passed architecture feasibility, so the next question is no longer whether a Transformer can be shared. We move to controlled diagnostics: temperature and CFG sweeps at fixed checkpoints, forced GT L0 or GT history, three-versus-five-level comparisons at the same step, and Laplacian residual measurements of how much new information each fine stage adds.
