01 / 排序诊断

空间生成顺序会在样本总体中留下方向性指纹

v0.18.x 不再把整图任意压成一条序列，而是比较 diagonal groups 与 column groups。v0.18.1 的 diagonal 模型留下了约 58k step 的实际样本；v0.18.2 的 column 分支留下了约 117k / 110k step 的样本。两组都能够形成图像，但它们的周期性结构并不相同。

v0.18.1 · diagonal groups · step 58k。模型能够生成整体结构，但分组边界仍可能在局部纹理中显现。

v0.18.2 · column groups · step 117k。与 diagonal 分组相比，纵向组织方式改变了误差的空间分布。

在 period-32 横向梯度统计上，column cohort 的 phase variation 约为 30.2%，diagonal cohort 约为 5.6%。这支持“分组方向会改变总体偏差”的判断，但不能推出每张 column 样本都有同一个 32-pixel 水印，也不能仅凭两个不同 checkpoint 断言哪一种排序质量更高。

诊断结论

空间 factorization 不是纯粹的工程细节：模型允许哪些位置先交流、哪些位置并行，会改变可见误差的方向与周期。

02 / 已有原型

v0.19.1 实现了最小 checkerboard A/B 路径，但没有结果

v0.19.1 把 256×256 图像切成 256 个 16×16 macro patches，再按 checkerboard 分为 A/B 两组。一个 phase 内的 128 个 patches 共享当前 pixel step，patch 内仍采用严格 raster-order Pixel AR；B phase 可以读取已经生成的 A phase。

组件当前状态能够说明什么
[1,16] coarse-to-patch hierarchy有实现tensor path 与两尺度接口已写出
A/B checkerboard + 128-patch batching有实现phase 内并行的代码路径存在
局部 16×16 Pixel AR + KV cache有实现patch 内因果生成组件存在
训练 checkpoint / log / sample未找到不能声称质量、速度或边界连续性改善

因此，v0.19.1 是 proof-of-concept implementation，不是 proof of effectiveness。它只把下一步的问题从“能否表达这个图”推进到“这个 factorization 是否值得训练”。

03 / 多层级 Phase Schedule

同一张图从 L0 到 L4 逐层提高分辨率：L0 全局 AR，后续层按 A/B phase 批量生成

交互图展示完整设计中的五层空间关系：L0-L4 分别生成 16²、32²、64²、128²、256² 的同一张图，对应每个 macro patch 内 1²、2²、4²、8²、16² 个 RGB pixels。L0 仍按传统 raster order 顺序生成 256 个 coarse RGB tokens；只有 L1-L4 才把 256 个 patches 拆成 A/B 两组，每组 128 个 patches 批量推进。它是对完整 Phase-Parallel HPA schedule 的可视化，不代表 v0.19.1 已经实现五层训练。

{% include research/refinement-v0191.html lang='zh' %}

一个 Shared HPA 主干，加一个轻量 Pixel AR head

顶层结构沿用 v0.17.7：所有 level 与 phase 都复用同一个 causal HPA Transformer，而不是为每层新建网络，但不同阶段使用不同的 token 粒度。L0 是传统 next-token AR：输入一个 coarse RGB token，再预测下一个。L1-L4 每次 phase 更替时，128 个 carrier tokens 作为一个 masked parallel group 同批进入 Shared HPA，并输出 128 个 patch conditions h_i。经过 AdaLN 调制后，轻量 Pixel AR head 仍在单个 patch 内逐 token 自回归，但 128 条 patch-local next-token loops 同时运行。动画为了便于理解，会在 L0 后把 A/B positions 画成连续两段；实际实现可直接通过 indices 与 causal mask 表达相同顺序，不需要真的移动 tokens。

训练。 把九组 stage 展开在同一张计算图中，用 stage mask 监督 HPA transition，并对每条 patch-local RGB 序列使用 teacher forcing。推理。 每次只运行图中高亮的一组 stage，采样轻量 Pixel AR head，把生成的 phase RGB 重新 embedding，再送回同一个 HPA 进入下一阶段。

资源影响目前仍只是设计估算。 逻辑序列仍为 256 + 8×128 = 1,280 个 HPA tokens。Rolling pre-eviction 预计常驻约 128 个 carrier tokens、峰值约 256；post-eviction 常驻约 256、峰值约 384，而 full history 最多为 1,280。把 B 当作更早 A 的压缩 carrier 仍是假设，必须用 full-history 对照验证；仅修改 block mask 也不会自动减少 dense-kernel FLOPs。

Implementation boundary

v0.19.1 已实现两阶段 checkerboard 与 patch batching，但它仍是 [1,16] 两层模型：phase communication 使用独立 bidirectional context layer，Pixel AR 读取单个 64-d prefix，而不是后文方案中的 shared Phase AR、rolling KV 或 AdaLN。

04 / 完整假设

把全串行 Patch AR 改成跨层、跨 phase、patch 内三种依赖

v0.17.7 已验证同一个 causal Transformer 可以跨 RGB 层级训练与采样；新设计只把每层内部的全序改成 A/B 两阶段偏序。

01

Coarse AR

L0 的 256 个 coarse RGB values 继续按全局顺序生成，负责语义与布局。

沿用 HPA 主干
02

Phase AR

L1-L4 先生成 A，再生成 B；共享大 Transformer 传递跨层和跨 phase state。

两阶段偏序
03

Patch RGB AR

同 phase 的 128 个 patches 并行推进当前 pixel，单个 patch 内保持 raster causal order。

局部严格 AR

完整五层方案的局部 Pixel AR 需要 2(4+16+64+256)=680 个同步 pixel rounds；再加 L0 的 256 轮与 8 次 phase transition，依赖路径约为 944。这个数字描述计算图，不是已经测得的加速比。

条件接口也需要从一个 64-d prefix 扩展为逐层调制：parent RGB、pixel position、level 与 phase 共同生成 AdaLN 参数。共享 Transformer 的 KV 则按 phase 滚动保留，以在显存和历史信息之间建立可测的取舍。

05 / 未知项

这套设计仍有五个必须单独回答的问题

  1. 01

    Phase 内条件独立是否过强？

    checkerboard 避免同 phase patches 共用水平或垂直边，但不保证颜色、纹理与长距离结构一致。

  2. 02

    A→B 通信是否真的有用？

    需要和 no A→B 对照，才能区分“checkerboard 划分”与“phase communication”的贡献。

  3. 03

    Teacher-forcing gap 出现在哪一段？

    sampled parent、sampled Phase A 与 sampled pixel history 必须分别替换，不能合并成一个 free-run 结果。

  4. 04

    AdaLN 是否读取了条件？

    correct、shuffled 与 zero condition 应产生可解释的 NLL 差异，否则调制路径可能被模型忽略。

  5. 05

    Rolling KV 何时清理？

    pre-eviction、post-eviction 与 full-history 需要同时比较质量、显存和 phase latency。

Current verdict

目前成立的是“空间排序会产生方向性偏差”与“phase-parallel 路径已经可实现”；尚未成立的是“它能提高质量、速度或边界连续性”。
