01 / 研究问题

真正昂贵的不是 AR，而是每个 patch 内重复去噪

在《像素级别的生成模型（三）》中，我们保留 Semantic AR，再用 diffusion 同步生成一个 patch 内的像素。这个结构可以避免逐像素采样时的局部语义冲突，但也带来一个直接的计算问题：如果一张图有 N 个 patches，每个 patch 需要 T 次去噪，那么像素头的调用次数就是 N × T。

本轮问题

能否保留 patch-level AR 的语义状态与 RGB 历史，同时把每个 patch 的生成从多步 diffusion / flow 缩成一次前向？

02 / Pixel-JiT

v0.11.9.3：把生成看成不断更新的 RGB 画布

早期 PAR baseline 的状态不是离散 token 序列，而是一张已经写入部分结果的 RGB 画布。Semantic AR Transformer 读取当前画布与目标位置，产生 patch-level condition h_t；Pixel head 再根据它生成当前 RGB patch，并立刻写回下一步输入。

生成合同

canvas_t → h_t → RGB patch_t → canvas_{t+1}。历史与输出都保持在像素空间，condition 负责压缩当前步骤所需的全局语义。

v0.11.9.3 网络结构：Semantic AR 读取当前 RGB 画布，pixel head 生成下一块 patch，并把结果写回后续上下文。架构 slide 现在放在方法正文，而不是标题旁。

free-run 样本已经能形成物体与场景，而不是只拟合局部颜色。这说明两个基础假设成立：RGB patches 可以作为 AR 上下文；一个共享 condition embedding 也确实能够指导下一块像素。但该实验没有证明这种方案高效，因为 pixel head 仍然需要在每一个 patch 上运行完整去噪轨迹。

v0.11.9.3 的代表性 free-run 结果。这里记录的是可行性与视觉现象，不把单张样本当作 FID 或总体质量结论。

英雄所见略同

Parallel Rollout Approximation（PRA） 在 2026 年 6 月公开了一个非常接近的问题起点：raw RGB patch 同时是当前步的连续目标，也是后续步骤的 causal context，整体保持 pixel-in、pixel-out 的 AR 接口。论文进一步把困难拆成高维 patch 的 single-step error 与 teacher forcing 引起的 train–inference gap——这也正是本项目后续 history 与层级实验反复遇到的两个问题。

PRA 的解决路径与 v0.11.9.3 不同：它生成低维 intermediate state，再通过 pixel decoder 回到 RGB，并用 parallel rollout approximation 构造 inference-like feedback。它不能反向证明我们的具体实现，但两条路线独立收敛到近似的问题定义，确实算得上一次很漂亮的“英雄所见略同”。

03 / 一步解码

v0.16：把“选择哪个模式”和“如何渲染像素”拆开

直接用 deterministic decoder 从 h_t 回归一个 patch，容易得到条件分布的平均值。v0.16 因此增加一个 token classification head：先从有限 codebook 中选择模式 z_t，再让一步 RGB decoder 同时读取 z_t 与 h_t。

对应的分解可以写成：

\[z_t \sim p_\theta(z\mid h_t),\qquad \hat{x}_t=g_\phi(z_t,h_t).\]

其中 CE head 负责多峰选择，decoder 只需要完成给定模式下的渲染。与 Pixel-JiT 相比，它取消了 patch 内的 denoise loop，把采样成本从“每个 patch 多步”变成“每个 patch 一次模式采样与一次解码”。

版本多峰选择像素生成主要限制
v0.11.9.3diffusion / flow 轨迹多步 patch head成本随 N × T 增长
v0.16.0token CE一步 RGB decoder仍依赖预训练 tokenizer / codebook

04 / 实验判断

一步生成是可行的，但 tokenizer 重新成为上限

v0.16.0 原始实验图（PPT 第 9 页嵌入素材，未包含幻灯片标题与标注）：物体级模式已经可见，但纹理和边界仍呈现 patchy failure。

  1. 01

    保留：像素画布的 AR 更新

    已生成 RGB 可以直接作为后续条件，不必先编码回 VQ latent。

  2. 02

    保留：显式的多峰选择变量

    一步 decoder 不应独自承担所有可能模式；先选 z_t 能避免纯回归平均。

  3. 03

    放弃：每个 patch 内完整去噪

    Pixel-JiT 的样本证明路线能跑，但重复 denoise loop 不符合我们对高效 Pixel AR 的目标。

  4. 04

    新瓶颈：预训练 tokenizer

    v0.16 的像素 I/O 看似直接，模式选择却仍由离散 codebook 定义；细节上限没有真正从 tokenizer 中释放出来。

05 / 留下的问题

下一步不是继续放大 codebook，而是替换它

这一轮没有得到可以公开比较的 FID，也没有证明 v0.16 在统一计算量下优于 diffusion head。可以确认的是结构性取舍：一步像素生成需要一个多峰接口，而现有 token CE 又把模型拉回 tokenizer 依赖。

因此下一篇将测试一个更直接的替代：不用预训练 codebook，把低分辨率 RGB 本身当作粗粒度“token”。如果它能够同时携带模式与布局，就可以保留一步 decoder，并把整个生成接口留在像素空间。
